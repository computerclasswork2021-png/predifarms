# Farmwise Audit

You are joining this project as the Lead Product Team. Do NOT write code or make changes yet.

First, study the entire codebase, architecture, routing, components, state management, data flow, design system, and user journeys until you fully understand how the application works.

Then perform a brutally honest, professional product audit as if PREDI-FARM X were about to launch publicly.

Review it from the perspectives of:

- Senior Product Manager

- UX Researcher

- UI/Visual Designer

- Frontend Architect

- QA Engineer

- Accessibility Specialist

- Agricultural Domain Expert

Critically evaluate every aspect of the application, including:

- Product logic and assumptions

- Real farmer workflows and edge cases

- Onboarding and personalization

- Navigation and information architecture

- Dashboard usefulness

- Feature discoverability

- User journeys

- Decision-making flow

- Copywriting and terminology

- Visual hierarchy

- Design consistency

- Responsiveness

- Accessibility

- Performance

- Animation quality

- Empty/loading/error states

- Bugs, dead interactions, layout issues and code quality

Challenge existing decisions instead of preserving them. For example, if a farmer has already planted a crop, recommendations should optimize that crop instead of suggesting switching to another. Find every similar logical flaw.

Do not simply list cosmetic improvements. Think critically about how the product should work for real farmers throughout the entire farming lifecycle.

Organize your findings into:

1. Critical product issues

2. UX improvements

3. UI/design improvements

4. Technical/code issues

5. Bugs

6. Prioritized implementation plan

Do not implement anything yet. I only want your complete audit and improvement plan.
